## 一、整体交易执行流程

### 1.1 主循环架构

```
每根K线 (4H):
  │
  ├─ 1. 检查锁仓期是否结束
  ├─ 2. 检查持仓 → 触发止盈/止损/爆仓
  ├─ 3. 轮动选币 → 选评分最高的信号
  ├─ 4. 判断 market regime (牛/震/熊)
  ├─ 5. 计算止损价 (sl_price)
  ├─ 6. 计算仓位 (margin → notional → units)
  ├─ 7. 硬风控校验 (保证金封顶 + 累计上限)
  ├─ 8. 计算止盈价 (tp_price)
  ├─ 9. 执行开仓 (写入 positions 数组)
  ├─ 10. 资金费率结算 (每8h)
  ├─ 11. 金字塔加仓检测
  └─ 12. 记录权益曲线
```

**代码位置**: `engine_core.py:729-780` (主循环 `run()`)

### 1.2 每一步的执行先后顺序（不可颠倒）

| 顺序 | 步骤 | 代码位置 | 说明 |
|:---:|------|----------|------|
| 0 | 策略产生买入信号 | `strategy.generate_signals()` | 输出 df['signal'] = 1/-1/0 |
| 1 | 轮动选币 | `_try_rotate_entry()` L886-951 | 多币种取 score 最高的 |
| 2 | 读市场状态 | `_try_rotate_entry()` L920 | row['regime'] = bull/range/bear |
| 3 | 读单笔建仓比例 | `_try_rotate_entry()` L937 | `alloc = init_alloc_pct / 100` |
| 4 | 进入 `_open()` | L1116-1283 | 核心仓位计算 |
| 4a | → 获取 regime_mult | L1144-1150 | 牛/震/熊 查表 |
| 4b | → 计算止损价 | L1158-1183 | **先于仓位计算** |
| 4c | → 计算仓位 | L1185-1208 | Fixed Capital / Fixed Risk 分支 |
| 4d | → 动态止损(Dynamic Stop) | L1210-1224 | 仓位确定后倒推止损线 |
| 4e | → 硬风控校验 | L1226-1240 | margin封顶 + 累计notional上限 |
| 4f | → 计算止盈价 | L1242-1252 | **最后算，不参与仓位** |
| 5 | 执行开仓 | L1265-1276 | 写入 positions[], 扣除手续费 |
| 6 | 持仓中检查 | `_check_positions()` L793-881 | 每根K线检查 TP/SL/爆仓 |
| 7 | 金字塔加仓 | `_check_pyramiding()` L953-1001 | 浮盈达标 → 追加 |
| 8 | 平仓结算 | `_close()` L1285-1334 | 盈亏入账 + 连亏计数 |

### 1.3 关键设计原则

> **先算 SL，再算仓位，最后算 TP。** 这个顺序决定了 Fixed Risk 模式能否正确工作——必须知道止损距离，才能倒推开仓量。

## 二、策略模式 Classic Direction 的逻辑

### 2.1 经典单向策略的参数体系

```
                    ┌─────────────────┐
                    │  单笔建仓比例%   │  ← 总阀门 (默认30%)
                    │  init_alloc_pct │
                    └───────┬─────────┘
                            │
           ┌────────────────┼────────────────┐
           ▼                ▼                ▼
    ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
    │  牛市乘数%   │  │  震荡乘数%   │  │  熊市乘数%   │
    │  bull_alloc │  │ range_alloc │  │  bear_alloc │
    │  默认 100%  │  │  默认 50%   │  │  默认 30%   │
    └─────────────┘  └─────────────┘  └─────────────┘
```

**三个参数的关系**: `init_alloc_pct` 是全局系数，三个市场乘数是条件分支。实际生效的是 `init_alloc_pct × 当市乘数`。

### 2.2 数值举例

**条件**: 账户 $10,000、ETH $2,000、4x 杠杆、单笔建仓比例 30%

| 市场 | 乘数 | 有效分配率 | 保证金 | 名义仓位 | ETH数量 |
|------|:---:|:---:|------:|------:|------:|
| **牛市** | 100% | 30% × 100% = **30%** | $3,000 | $12,000 | 6.0 ETH |
| **震荡** | 50% | 30% × 50% = **15%** | $1,500 | $6,000 | 3.0 ETH |
| **熊市** | 30% | 30% × 30% = **9%** | $900 | $3,600 | 1.8 ETH |

### 2.3 代码依据

```python
# engine_core.py L937
alloc = self._init_alloc_pct / 100.0          # 例: 30 → 0.3

# engine_core.py L1144-1150
if regime == 'bull':   regime_mult = bull_alloc   # 1.0
elif regime == 'bear':  regime_mult = bear_alloc  # 0.3
else:                  regime_mult = range_alloc  # 0.5

# engine_core.py L1201 (Fixed Capital)
margin = equity × regime_mult × alloc
       = 10000 × 1.0 × 0.3 = 3000  (牛市)
       = 10000 × 0.5 × 0.3 = 1500  (震荡)
       = 10000 × 0.3 × 0.3 = 900   (熊市)
```

## 三、仓位模式详细说明

### 模式 A: Fixed Capital (固定资金比例)

#### 用户输入
- 单笔建仓比例% (如 30%)
- 牛市%/震荡%/熊市% (如 100/50/30)
- 杠杆倍数 (如 4x)
- 止损% (如 5% 保证金)

#### 系统计算公式

```
Step 1: regime_mult  = 查表(regime)            # 牛市=1.0, 震荡=0.5, 熊市=0.3
Step 2: alloc        = 建仓比例% / 100          # 30% → 0.3
Step 3: margin       = equity × regime_mult × alloc
Step 4: notional     = margin × leverage
Step 5: position_units = notional / fill_price  # ETH 数量
```

#### 核心公式

$$\text{margin} = \text{equity} \times \text{regime\_mult} \times \frac{\text{init\_alloc\_pct}}{100}$$

$$\text{notional} = \text{margin} \times \text{leverage}$$

#### 止损距离的角色

在 Fixed Capital 模式下，止损距离**不参与仓位计算**。止损只决定什么时候平仓，不影响开多少仓。

#### 杠杆参与位置

杠杆在 **Step 4** 参与：`notional = margin × leverage`。杠杆越大，同样的保证金撬动的名义仓位越大，同样的价格波动造成的盈亏越大。

---

### 模式 B: Fixed Risk (固定风险比例)

#### 用户输入
- 单笔建仓比例% (如 30%)
- 牛市%/震荡%/熊市% (如 100/50/30)
- 杠杆倍数 (如 4x)
- 止损% (如 5% 保证金)
- **单笔风险占比%** (如 2%) ← 核心差异参数

#### 系统计算公式

```
Step 1: regime_mult  = 查表(regime)
Step 2: alloc        = 建仓比例% / 100
Step 3: sl_price     = fill_price × (1 - 止损%/杠杆)  [margin_pct模式]
        sl_distance  = abs(fill_price - sl_price)     ← 每单位亏损距离($)
Step 4: risk_budget  = equity × 风险% × regime_mult × alloc
Step 5: units        = risk_budget / sl_distance
Step 6: notional     = units × fill_price
Step 7: margin       = notional / leverage
```

#### 核心公式（简化形式）

$$\text{margin} = \text{equity} \times \frac{\text{risk\_pct}}{\text{sl\_pct}} \times \text{regime\_mult} \times \frac{\text{init\_alloc\_pct}}{100}$$

> **等号右边出现了 `risk_pct / sl_pct`**。这意味着：
> - 当 risk% = sl% 时，两者抵消，公式退化为 Fixed Capital
> - 当 risk% < sl% 时，仓位按比例缩小
> - **这是设计特性，不是 Bug**。UI 已添加警告。

#### 止损距离的角色

在 Fixed Risk 模式下，止损距离**直接参与仓位计算**（Step 5 的分母）。止损越宽 → sl_distance 越大 → units 越小 → 仓位越轻。

#### 杠杆参与位置

杠杆在**两处**参与：
1. Step 3: 止损距离 `sl_distance = fill × sl_pct / leverage` ← 杠杆影响 sl_distance
2. Step 7: `margin = notional / leverage` ← 杠杆将名义价值换回保证金

**两处互相抵消**。最终：杠杆不影响 Fixed Risk 模式下的保证金规模，只影响 `sl_distance` 的计算。

#### 数值对比举例

**条件**: 牛市、账户 $10,000、ETH $2,000、4x 杠杆、建仓 30%、止损 5% 保证金

| risk% | 风险预算 | 保证金 | 名义仓位 | vs Fixed Capital |
|:---:|------:|------:|------:|:---:|
| 1% | $60 | $600 | $2,400 | 20% |
| 2% | $120 | $1,200 | $4,800 | 40% |
| 5% | $300 | $3,000 | $12,000 | 100%（收敛） |
| 10% | $600 | $6,000 | $24,000 | 200%（被风控封顶） |

## 四、margin、notional、position_units 关系

### 4.1 定义

| 变量 | 含义 | 公式 | 类比 |
|------|------|------|------|
| **margin** | 保证金：从账户中锁定的资金 | `notional / leverage` | 买房的首付 |
| **notional** | 名义价值：实际控制的资产规模 | `margin × leverage` | 房子的总价 |
| **position_units** | 持仓单位：持有多少个标的 | `notional / fill_price` | 买了几套房 |

### 4.2 举例

**条件**: 账户 $10,000、ETH $2,000、4x 杠杆、建仓 30%

```
margin         = $10,000 × 30% = $3,000        ← 锁定了 $3,000
notional       = $3,000 × 4 = $12,000          ← 实际控制了 $12,000 的 ETH
position_units = $12,000 / $2,000 = 6.0 ETH    ← 持有 6 个 ETH

验证: 6 ETH × $2,000/ETH = $12,000 ✓
      $12,000 / 4 = $3,000 ✓
```

### 4.3 是否存在杠杆重复计算？

**不存在。** 杠杆在系统中只用了**一次**：

```
notional = margin × leverage       (开仓时)  ← 正向使用
margin   = notional / leverage     (反推时)  ← 逆向使用
```

这两个操作是互逆的，不会造成重复放大。

## 五、止盈止损系统

### 5.1 当前支持两种模式

| 止损/止盈模式 | 含义 | 计算公式 |
|------|------|------|
| **保证金% (Margin%)** | 保证金盈亏达到 X% | `sl_price = fill × (1 ± sl_pct/lev)` |
| **价格% (Price%)** | 标的价格波动达到 X% | `sl_price = fill × (1 ± sl_pct)` |

**代码位置**: `engine_core.py:1158-1169` (SL), `engine_core.py:1242-1252` (TP)

### 5.2 保证金%模式举例

**条件**: ETH $2,000、4x 杠杆、止盈 10%、止损 5%

| 事件 | 计算公式 | 价位 | 价格变化 | 保证金盈亏 |
|------|------|------|:---:|:---:|
| **止盈触发** | `2000 × (1 + 10%/4)` | **$2,050** | +2.5% | +10% × 杠杆 = +10% |
| **止损触发** | `2000 × (1 - 5%/4)` | **$1,975** | -1.25% | -5% × 杠杆 = -5% |

### 5.3 价格%模式举例

| 事件 | 计算公式 | 价位 | 价格变化 | 保证金盈亏 |
|------|------|------|:---:|:---:|
| **止盈触发** | `2000 × (1 + 10%)` | **$2,200** | +10% | +10% × 4 = **+40%** |
| **止损触发** | `2000 × (1 - 5%)` | **$1,900** | -5% | -5% × 4 = **-20%** |

### 5.4 持仓中检查机制

每根 K 线，`_check_positions()` 检查持仓的 high/low 是否穿越了 TP/SL 价位：

```python
if side == 'LONG':
    t_hit = high >= tp_price   # 最高价是否触及止盈
    s_hit = low <= sl_price    # 最低价是否触及止损
```

**同时触及时**: 保守取 SL（worst-case execution），代码在 L811-812。

## 六、ATR 动态止损逻辑

### 6.1 执行顺序

```
① 先按 UI 止损% 算出 sl_price  (如 5%保证金 → $1,975)
         │
         ▼
② 如果勾选了 ATR → 立即覆盖!
   sl_price = fill_price - ATR(14) × 倍数
   例: $2,000 - $40 × 2 = $1,920
         │
         ▼
③ 用新的 sl_price 参与仓位计算
   sl_distance = abs(fill - sl_price)
```

**代码位置**: `engine_core.py:1171-1181`

### 6.2 ATR 模式下的止损行为

| 场景 | 使用的止损 |
|------|------|
| ATR 未开启 + UI 止损% = 5% | UI 止损%（$1,975） |
| ATR 开启 + ATR 周期 14 + 倍数 2 | **ATR 算出的价格**（$1,920） |
| ATR 开启，但 K 线无 ATR 数据 | 回退到 `fill_price × 1%` 作为 ATR（兜底） |

**UI 止损% 在 ATR 开启时完全失效。**

### 6.3 ATR 止损是开仓时固定还是动态更新？

**开仓时一次性定价，持仓期间不更新。**

理由：代码在 `_open()` 中计算一次 `sl_price`，写入 `pos['sl_price']`，`_check_positions()` 中只做固定值比较（L803 `sl_px = pos['sl_price']`），没有重新计算 ATR。

持仓期另有独立机制：**移动止损 `trailing_pct`**，从开仓后的最高价回撤 X% 触发平仓，不与 ATR 交互。

## 七、Fixed Capital 与 Fixed Risk 的参数关系

### 7.1 "单笔风险占比%" 为什么在 Fixed Capital 下不可修改？

**这是正确设计，不是 UI Bug。**

| 仓位模式 | 单笔风险占比% 的行为 | 原因 |
|------|------|------|
| Fixed Capital | 显示为 "N/A"，不可修改 | 该模式下仓位由保证金比例决定，风险由止损%控制，不需要额外的风险预算参数 |
| Fixed Risk | 完全可编辑，0.1% ~ 30% | 这是 Fixed Risk 模式的核心参数——决定每笔最多亏多少 |

**代码位置**: `app.py:906-916`

### 7.2 产品建议

> **保留当前设计。** Fixed Capital 下显示 "N/A" 是正确的 UX，避免用户误以为这个参数会影响仓位。

## 八、牛熊市场过滤系统

### 8.1 市场状态判断来源

每个 K 线通过 `MultiFactorRegime.evaluate()` 打标：

```python
df['regime'] = 'bull'   # 综合评分 > 牛市阈值
             = 'bear'   # 综合评分 < 0 (空头主导)
             = 'range'  # 中间地带 (震荡)
```

市场状态**不是策略信号**——它是独立的宏观环境判断，每根 K 线都计算。

### 8.2 如何影响仓位

| 市场 | 环境乘数 | Fixed Capital 效果 | Fixed Risk 效果 |
|------|:---:|------|------|
| bull | 100% (默认) | 保证金 = equity × 100% × 建仓% | 风险预算 = equity × risk% × 100% × 建仓% |
| range | 50% (默认) | 保证金**减半** | 风险预算**减半** |
| bear | 30% (默认) | 保证金**缩到 30%** | 风险预算**缩到 30%** |

**两个模式都受影响，乘在同一个位置。**

### 8.3 熊市 30% 举例

```
牛市: margin = 10000 × 1.0 × 0.3 = $3,000 → notional = $12,000
熊市: margin = 10000 × 0.3 × 0.3 = $900   → notional = $3,600

熊市仓位缩小到牛市的 30%。每次止损亏损:
牛市: $12,000 × 1.25% = $150
熊市: $3,600 × 1.25% = $45
```

### 8.4 设为 0% 的特殊行为

如果用户将某市场乘数设为 0%，该市场状态下**完全不开仓**。

```python
# engine_core.py L1152-1156
if regime_mult <= 0:
    if self.verbose:
        print(f"[BLOCKED] {regime}市场乘数=0%, 跳过开仓")
    return  # 直接退出, 不开仓
```

## 九、金字塔加仓系统

### 9.1 参数体系

| UI 参数 | 代码变量 | 默认值 | 含义 |
|------|------|:---:|------|
| 启用加仓 | `_enable_pyramiding` | False | 总开关 |
| 触发条件% | `_pyr_trigger_pct` | 2.0% | 持仓均价浮盈超过此%触发加仓 |
| 加仓比例% | `_pyr_add_pct` | 50% | 每次加仓占初始仓位的百分比 |
| 最大加仓次数 | `_pyr_max` | 3 | 最多加几次 |
| 保本止损 | `_pyr_trail` | False | 加仓后移动止损至均价 |

### 9.2 执行逻辑

```
每根K线检查:
  1. 当前持仓浮盈 > 触发条件% ?
     → side=LONG: px >= avg_entry × (1 + trigger)
     → side=SHORT: px <= avg_entry × (1 - trigger)

  2. 当前加仓次数 < 最大次数 ? 且未锁仓 ?

  3. 满足 → 执行加仓:
     add_margin  = equity × 加仓比例%
     add_notional = add_margin × leverage
     _open(coin, side, px, add_pct, ...)  ← 复用开仓逻辑

  4. 加仓后:
     - 重新计算加权均价 (按名义价值加权)
     - 重新计算 TP/SL 价格
     - 如果启用保本止损: SL = 新均价
```

### 9.3 是否可能无限加仓？

**不可能。** 硬限制：
- 最大加仓次数 `_pyr_max`（默认 3，最多 10）
- 累计名义仓位不超过 `equity × max_notional_pct`（默认 ×5）
- 每次加仓用 `_pyr_add_pct` × equity 做保证金

### 9.4 最大风险

假设牛市、建仓 30%、加仓 3 次、每次 50%：
```
首仓:     $3,000 保证金 → $12,000 notional
加仓 1:   $1,500 保证金 → $6,000 notional
加仓 2:   $1,500 保证金 → $6,000 notional
加仓 3:   $1,500 保证金 → $6,000 notional
────────────────────────────────────
总计:     $7,500 保证金 → $30,000 notional (3x 权益)
```

但受 `max_notional_pct = 5.0` 约束：最多 $50,000 notional → 最多加 3 次（$30,000 < $50,000）。

**风险**: 如果连续加仓后反转，止损触发时账户可能亏掉累计的 $7,500 保证金。保本止损 (`pyr_trail`) 可以缓解这个风险。

## 十、参数优先级表

| 优先级 | 参数名称 | 覆盖关系 | 影响对象 |
|:---:|------|------|------|
| **1 (最高)** | ATR 动态止损 | 完全覆盖 UI 止损% | 止损价 |
| 2 | 硬风控封顶 (margin > equity) | 覆盖所有仓位计算结果 | margin, notional |
| 3 | max_notional_pct (累计上限) | 覆盖所有仓位计算结果 | notional |
| 4 | 市场乘数 (牛/震/熊%) | 缩放 Fixed Capital 和 Fixed Risk 的仓位 | margin, risk_budget |
| 5 | 单笔建仓比例% | 总阀门，与市场乘数相乘 | margin, risk_budget |
| 6 | 仓位模式 (Fixed Capital/Risk) | 决定走正算还是倒推分支 | 整个仓位公式 |
| 7 | 单笔风险占比% | 仅在 Fixed Risk/Dynamic Stop 下生效 | risk_budget |
| 8 | 止损% (sl_pct) | Fixed Capital: 只影响平仓触发 | sl_price, exit timing |
|  |  | Fixed Risk: 同时影响仓位(分母) + 平仓 | sl_price, margin |
| 9 | 止盈% (tp_pct) | 只影响平仓触发，不参与仓位 | tp_price |
| 10 | 移动止损 trailing_pct | 覆盖原始 SL 价 | sl_price (动态) |
| 11 | 金字塔加仓 | 叠加仓位，受累计上限约束 | 总仓位 |
| **最低** | 连亏锁仓 | 强制暂停开仓 | 开仓时机 |

### 优先级冲突场景

**场景 1**: ATR 开启 → UI 止损% 被覆盖，但 Fixed Risk 仓位计算用的是 ATR 算出的 sl_distance。

**场景 2**: Fixed Risk 算出 margin=$20,000 > equity=$10,000 → 硬风控封顶到 $10,000。用户看到的是"实际仓位 < 理论仓位"。

**场景 3**: 熊市乘数=0% → 所有其他参数失效，直接不开仓。

### 已知设计缺陷

| 缺陷 | 严重度 | 说明 |
|------|:---:|------|
| **`except: pass` 静默吞错** | 🔴 已修复 | `run()` 参数读取异常被静默跳过，现已改为显式报错 |
| **Dynamic Stop 未加入 UI** | 🟡 | 引擎已支持但 UI 无对应选项 |

> 当前平台处于 **回测研究阶段 (B)**。引擎核心逻辑完整，可以用于策略研发和参数优化。但要进入实盘，至少需要补充：**交易所 API 对接、实时行情、订单管理系统 (OMS)、仓位同步对账、异常恢复** 五大模块。
