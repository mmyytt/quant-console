## 一、产品目标

### 当前平台能力
- 多品种回测 (ETH/BTC/SOL)
- 多周期回测 (5m/15m/1h/4h/1D)
- 27种技术指标自由组合
- 三种策略范式 (经典单向/Delta对冲/动能解封)
- 收益分析 + 风险指标展示
- OOS样本外验证
- AI策略诊断

### 当前局限
用户只能知道"这个策略赚了多少钱"，无法知道：
- **为什么赚钱？** 收益来源是趋势跟踪还是均值回归？
- **收益是否可信？** 是否存在过拟合、未来函数、数据泄露？
- **最大风险在哪里？** 最大回撤发生在什么行情下？
- **是否适合实盘？** 策略在真实摩擦成本下还能盈利吗？

### 升级目标
将平台从**"策略回测工具"**升级为**"专业量化研究分析平台"**。新增AI量化审计中心，让用户不仅看到结果，还能理解结果背后的原因和可信度。

---

## 二、核心产品理念

### 必须遵守的原则

1. **数据负责证明。AI负责解释。**
2. 所有基础数据必须由程序计算（杜绝AI编造）
3. AI不能修改任何回测数据
4. AI不能凭空评价策略
5. AI只能基于Audit Engine输出结果进行分析
6. **高收益不代表高评分**（策略评估是多维度的）

## 五、Audit Engine 功能详细规格

回测结束后生成结构化审计数据，必须包含以下维度：

### 5.1 收益分析
| 指标 | 说明 |
|:---|:---|
| 总收益率 | Total Return % |
| 年化收益 | Annualized Return % |
| 年度收益 | Year-by-Year Returns |
| 月度收益 | Monthly Returns Heatmap |
| 收益稳定性 | 年度收益标准差 |

### 5.2 风险分析
| 指标 | 说明 |
|:---|:---|
| 最大回撤 | Max Drawdown % |
| 最大回撤时间 | 回撤起止日期 |
| 回撤恢复时间 | 从回撤谷底恢复到前高所需天数 |
| 波动率 | 日收益率标准差年化 |
| Sharpe Ratio | ✅ 已有 |
| Sortino Ratio | ✅ v3.x新增 |
| Calmar Ratio | ✅ v3.x新增 |
| 最大连续亏损 | ✅ v3.x新增 |

### 5.3 交易分析
| 指标 | 说明 |
|:---|:---|
| 总交易次数 | Total Trades |
| 胜率 | Win Rate % |
| 盈亏比 | Profit Factor |
| 平均盈利 / 平均亏损 | Avg Win / Avg Loss |
| 最大单笔亏损 | Max Single Loss |
| 多空交易比例 | Long/Short Trade Split |

### 5.4 策略稳定性
| 检查项 | 方法 |
|:---|:---|
| Walk Forward验证 | 训练→验证→测试三段评估 |
| 参数敏感性 | 测试EMA/RSI阈值变化对收益的影响 |
| 过拟合风险检测 | OOS年化衰减率 + Walk Forward鲁棒性评分 |

### 5.5 实盘真实性检查
| 检查项 | 说明 |
|:---|:---|
| 手续费 | 是否按名义本金扣除 0.05% Taker |
| 滑点 | 是否计入 ±0.02% 滑点 |
| Funding Rate | 是否模拟每8h资金费率 |
| 保证金占用 | 是否真实冻结保证金 |
| 强平模拟 | 是否检测维持保证金率触发强平 |

## 六、策略评分系统 (Strategy Scoring)

### 总分 = 70%程序评分 + 30% AI综合评价

### 程序评分 (70分)

| 维度 | 满分 | 评分依据 |
|:---|:---|:---|
| **收益能力** | 20 | 年化收益: >50%=20分, >20%=15分, >0%=10分, 负=5分 |
| **风险控制** | 20 | 最大回撤: <20%=20分, <35%=15分, <50%=10分, >50%=5分 |
| **风险收益比** | 15 | Calmar Ratio: >2=15分, >1=10分, <1=5分 |
| **稳定性** | 10 | Walk Forward鲁棒性: >80=10分, >50=7分, <50=4分 |
| **实盘真实性** | 5 | 全部摩擦成本已扣除=5分, 缺失部分=3分 |

### AI评价 (30分)

AI基于审计数据，评价：
- 策略逻辑质量
- 收益来源是否合理
- 主要风险来源
- 实盘适用性建议

## 七、AI 报告设计规范

### 报告内容结构

1. **策略综合评分** (如: 82/100)
2. **专业研究分析** (机构量化报告风格)
3. **通俗解释** (每个专业分析后配大白话)
4. **风险提示** (策略最大风险点)
5. **优化建议** (优先风控/仓位/鲁棒性)

### 通俗解释要求

| 专业术语 | 通俗解释模板 |
|:---|:---|
| "存在Alpha衰减风险" | "简单来说，过去有效的方法未来可能因为市场变化降低效果" |
| "Sharpe Ratio < 0.5" | "每一分钱的收益承担了较大的波动风险" |
| "Max Drawdown > 50%" | "这个策略历史上曾经腰斩过，实盘可能无法承受" |
| "Walk Forward鲁棒性低" | "在没见过的数据上表现变差，可能存在过度优化" |

### 优化建议优先级
1. 风险控制 (止损/仓位)
2. 仓位管理 (杠杆/资金利用率)
3. 鲁棒性提升 (过拟合修正)
4. **不要**简单建议"增加更多指标"

## 八、指标解释系统

平台包含27+种技术指标，需要解释能力。

### 每个指标必须提供

| 字段 | 说明 | 示例 (ADX) |
|:---|:---|:---|
| 专业定义 | 技术定义 | Average Directional Index, 趋势强度指标 |
| 通俗解释 | 大白话 | "判断市场有没有明显方向，像风一样有方向和力度" |
| 使用目的 | 为什么用 | 过滤震荡市，只在强趋势时交易 |
| 优缺点 | 坦诚说明 | 优点: 客观判断趋势; 缺点: 滞后，震荡市频繁假信号 |

## 九、防止 AI 幻觉 (Anti-Hallucination)

### AI模块必须遵守的禁令

- ❌ 禁止编造交易记录
- ❌ 禁止修改回测收益
- ❌ 禁止保证未来盈利
- ❌ 禁止预测未来收益
- ✅ 只能基于Audit Engine输出的结构化数据进行分析
- ✅ 所有数字引用必须来自程序计算结果

### 技术实现
- `generate_audit_report()` 生成纯数据报告
- AI Prompt 注入: "你只能基于以下审计数据进行分析，不要编造任何数字"
- 前端展示时区分: 蓝色=程序数据 / 绿色=AI分析
